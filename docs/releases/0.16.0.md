# Myna 0.16.0

This release makes Truffle cells that lend buffers, and every FFM cell, compile into their callers,
adds an allocation-free entry for host code, and gives the macOS LLVM applicator a debug identity
that follows its debug information.

## Truffle cells

- A borrow acquired and released by a compiled cell is no longer allocated. `BytesCoercion.execute`
  needed a class-initialization check, which kept it out of runtime compilation: compiled code
  called it as an opaque function and received a heap `Borrow` (48 bytes per byte parameter).
  Lending native memory and scratch copies now costs no Java heap; a pin costs only its
  `PinnedObject`, as a hand-written pin does.
- FFM cells call their bindings from a static method behind a `@TruffleBoundary`. Their bodies
  were excluded from runtime compilation for the same reason, so each call allocated its argument
  array and boxed carriers (32 bytes) and took about twice the direct FFM call.
- Every cell except a resource's `destroy` has a `public static invoke` with native carriers and
  raw `long` addresses: no `Object[]`, boxes, `NativePointer` or `Borrow`. It is the entry for
  host code compiled ahead of time, where none of those objects are scalar-replaced; the cell's
  `execute` methods coerce and then call it.
- Byte parameters compile only the kinds of value a call site has lent, and `NativeBytes` lends its
  address without a call through the segment interface.
- `tests/truffle_integration.py` fails if a cell or coercion is missing from the image's
  runtime-compilation listing, or if a compiled call allocates.

Measured on one shared Apple M5 Max (advisory): a ten-argument leaf cell over native buffers went
from 8.4 ns and 96 B per call to 3.0 ns and 0 B, its transitioning form from 12.1 ns to 5.6 ns,
and FFM cells from 9.3 ns and 32 B to 4.6 ns and 0 B. Scalar leaf and transition cells are
unchanged. A transitioning call costs the same through a cell, a `boundary` cell and a
hand-written `@TruffleBoundary`; see the [cells guide](../truffle-cells.md#measurement).

Generated `*Truffle.java` sources change shape (the binding call moves into `invoke`); regenerate
them. Code that relied on `Borrow.none()` being the object a coercion returns for a null argument
must compare the address instead.

## Symbols

- The macOS LLVM applicator links a `__TEXT,__myna_debug_id` section holding a digest of its
  object files, so its Mach-O UUID changes whenever its debug information can. Before, a source
  change that only moved lines produced a byte-identical executable with the same UUID and a
  different dSYM (v0.9.1 and v0.10.0; v0.11.0 and v0.12.0), which the symbol server rejects.
  Identical inputs still reproduce identical executables and sidecars. Sidecars already stored
  under those UUIDs are left as they are.

The generator version changes every fingerprint; regenerate matching outputs together and
rebuild native libraries against them. Binding ABI 2 and native value ABI v3 are unchanged.
No existing published artifacts or tags are replaced.
