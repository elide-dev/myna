# Myna 0.20.0

This release adds persisted formats (#167): versioned binary formats, declared in the descriptor,
with a canonical writer and a validating reader generated for both Rust and Java. It also lets the
Rust records live in a different crate from the implementation checks (#166), fixes raw `BigInteger`
arguments to Truffle cells (#150), and moves the pinned Graal distribution to 25.5.5-elide.31. There
are no breaking changes to existing descriptors. The C ABI, carriers, layouts, symbols, `seam.ll`
contracts and `BINDING_ABI_VERSION` (2) are unchanged. Fingerprints change for every descriptor, as in
every release.

## Persisted formats (#167, #169)

A descriptor can now declare formats that are written to disk and read back later, possibly by the
other language. See [formats.md](../formats.md) for the full reference.

- `family` groups the declarations that formats share: `node` types (`sharing=interned|unique`),
  inline `element`s, `kind`s (closed sets of nodes) and tagged `union`s. Several formats can share one
  family.
- `format NAME family=F version=N magic=M pinned=HEX16 … end` declares a format, with five required
  `limit` lines, an optional `header` word and a `root` line.
- Node members are scalar `field`s (with `enum=`/`flags=` closed sets and `type=bytes`), `string`s
  (interned string-table ids), `ref`/`refs` (backward references to a node, a kind or `any`, optionally
  `optional=true`) and `list`s of scalars, untagged elements or a union.

**Wire format.** A 40-byte header, an interned string table, packed little-endian nodes in depth-first
post-order and a trailing offset index. The encoding is canonical: a value has exactly one byte sequence,
whatever order the writer created its nodes in, so encoded bytes can be compared and used as keys.

**Validation.** The readers make one forward pass over structure, limits, closed sets, string order and
references (backward and in range; a `unique` node referenced at most once), then check canonical form.
Validation is all-or-nothing, never recurses or panics, and bounds its allocations by checked counts.
`max_work` bounds what a naive recursive walk of the validated tree can cost, so a file cannot blow up
through sharing. There are 31 error kinds with stable codes, and the Rust and Java readers report the
same `(kind, offset, node)` for every input.

**Versioning.** Each file carries a layout fingerprint that ignores names, limits and the generator
version, so renames, limit changes and Myna upgrades leave existing files valid. `pinned=` fails
generation when the layout changes without a version bump. A format without `pinned=` must say
`draft=true`; `myna validate` and `myna generate` then print `draft format NAME pinned=HEX16`, the value
to pin.

**Generated code.**

- Rust, in `formats.rs` (`no_std` + `alloc`): typed `Copy` views with iterators for lists and enums for
  kinds and unions, and a writer with typed ids. Ids of `unique` nodes are not `Copy`, so reusing one is
  a compile error. List arguments take any `IntoIterator`. The file allows `dead_code` and
  `unreachable_pub`, so it can be included as a private module.
- Java, pure Java over `byte[]`: static accessors and element cursors, a `check` that returns `null` or
  `{kind, offset, node}`, and a writer that takes records and a sealed union interface. There is no
  `MemorySegment` reader: in a Native Image, segment reads measured about 70 times slower than `byte[]`
  (elide-dev/graal#250).

**Names and diagnostics.** Format declarations only have to avoid Rust and Java keywords, not C or C++
ones, so `inline` and `template` work. A generated name that would be a keyword gets a trailing `_`
(node `Return` gets writer method `return_`). Validation errors give the declaration and its line, for
example `line 37: node Root: member type is a Rust keyword`.

**Formats-only modules.** A module that declares formats and no call boundary (no opaque, struct,
callback, function, resource or borrow, and no Truffle cells) generates only `seam.json`, `seam.abi`,
`seam.rs`, the Java constants class and the format files. `seam.h`, `seam.ll` and the Native Image and
FFM classes are not written.

`mise run test:formats` checks that both writers reproduce the golden bytes in two creation orders, that
every golden file round-trips, that both readers agree on dumps and verdicts (including 1600 seeded
corruptions and one crafted input per error kind), and that a second descriptor compiles in both
languages. A Native Image integration test runs the Java writer and reader in an image.

**Not yet:** Rust enum and flag fields take and return raw integers rather than the typed values in
`seam.rs`, because `formats.rs` is standalone.

## Rust records and implementation checks in separate crates (#166, #171)

For a module with imports, `myna generate` also writes `seam.rs` in two parts:

- `seam_types.rs` holds the records: every type, constant, `extern` declaration, wrapper, the
  `ownership` module and the `rust_implementation=trait` trait.
- `seam_impl.rs` holds only the implementer macros: `assert_implementations!`,
  `define_implementations!` and `native_image_shims!`.

`seam.rs` is exactly `seam_types.rs` followed by the macros, so existing builds are unchanged. In
`seam.rs` the macros now come after the `ownership` module. Because the macros name every record through
their path argument, a crate that includes only `seam_impl.rs` can run them against records defined in
another crate:

```rust
// crate `records`
pub mod seam { include!(concat!(env!("SEAM_GENERATED"), "/seam_types.rs")); }

// crate `implementation`, depending on `records`
mod checks { include!(concat!(env!("SEAM_GENERATED"), "/seam_impl.rs")); }
checks::define_implementations!(Demo, records::seam);
checks::assert_implementations!(records::seam);
```

Each macro form that takes a path compares that module's `ABI_FINGERPRINT` with the fingerprint the
macros were generated from, at compile time. Records and checks from different descriptors fail with
`records and checks come from different ABIs` instead of linking mismatched entry points. See
[ownership.md](../ownership.md#records-and-implementation-in-separate-crates).

## Fixes

- **#150** (#154): a Truffle cell rejected a plain `java.math.BigInteger` argument, because Truffle
  interop does not treat a host `BigInteger` as a number. That made u64 and usize magnitudes in
  `[2^63, 2^64)` unusable from host code. Integer coercion now accepts a raw `BigInteger` on the same
  terms as an interop number of the same value, under both `STRICT` and `WRAP`, and a monomorphic
  `BigInteger` call site still adds no `InteropLibrary` node.

## Generated files

If you check generated output in, expect these new files: `seam_types.rs` and `seam_impl.rs` for
modules with imports, and `formats.rs` plus the Java format classes for modules that declare formats.

## Dependencies

- The pinned elide-dev/graal distribution and the Truffle and SDK Maven pins move from 25.5.5-elide.28
  to 25.5.5-elide.31 (#168). The toolchain stays 2026.11.7.
- Build and CI: `jdx/mise-action` 5.2.9 (#138, #170), `build-helper-maven-plugin` (#162, #163) and
  Maven 3.10.1 for the benchmarks (#164).
- Docs: a struct `NAME` is allowed for in-place handled resource creates (#156).

Regenerate matching outputs together and rebuild native libraries against them. Binding ABI 2 and native
value ABI v3 are unchanged. No existing published artifacts or tags are replaced.
